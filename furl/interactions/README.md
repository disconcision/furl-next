# Interaction studies

A separate design document for source-editing gestures. It does not modify the live Furl editor or use its browser storage.

- `inventory.json`: ordered stages and sourced actions, with separate Study/Hazel coverage, remaining work, targets, semantic operations and mouse/keyboard equivalents.
- `stories.js`: eight fixed before/after programs; values are presets.
- `study.js`: arithmetic row lab, reference-placement lab, storyboard renderer, and inventory filters.
- `wire.js`: SVG wires with word-center anchors, damped-spring bends, and retracting unplugged endpoints.
- `page.html`, `style.css`: document and Furl presentation, sharing `../reference/book.css`.
- `build.py`: inlines everything into `docs/interactions.html`; Python standard library only.
- `test.cjs`: browser-level input, transaction, and offline checks, including `motion-test.cjs` for intermediate animation frames and `cell-mode-test.cjs` for whole-row dragging and cell activation, and `wire-test.cjs` for connections, hover, anchors, word insertion, and wire motion. `tool-test.cjs` checks the shared palette/policy, slot motion, deletion, unplugging, keyboard equivalents, and cancellation. `connection-cancel-test.cjs` covers click-away cancellation, missed binder drags, policy independence, retraction, consumed clicks, and reduced motion. `inventory-test.cjs` checks coverage rendering, grouped filters, example/storyboard links, deep links and responsive layout.

```sh
python3 furl/interactions/build.py
python3 furl/interactions/build.py --check
node --check furl/interactions/study.js
node --check furl/interactions/stories.js
node --check furl/interactions/wire.js
node furl/interactions/test.cjs
```

The browser test requires Playwright and installed Chrome (make Playwright available through `NODE_PATH` if needed). It defaults to opening the generated artifact with `file://`, aborts external requests, and writes screenshots to a temporary directory. `TEST_URL` can point it at a served copy. Motion checks pause browser animations and seek through insertion, rapid drag reversals, drop, and refusal. They assert painted positions as well as final row order; the previous append-and-measure loop fails the first insertion-frame check.

The row lab uses ordinary HTML inputs and a small JavaScript parser, with no Hazel editor or backend. It accepts numbers, identifiers, parentheses, unary minus, addition, subtraction, and multiplication; it never evaluates input as JavaScript. The refactor gate checks valid arithmetic and unique, in-scope names before and after a move. Completely blank drafts are omitted from that check because they bind and use no names, but remain visible as holes. Other invalid or incomplete arithmetic still blocks Refactor; this is not Hazel refactoring. Reload resets both labs; Undo is session-local.

Row motion tracks stable IDs: capture current painted positions, cancel old tweens, complete all DOM moves, measure final positions, then animate the displacement. This ordering matters when a new preview interrupts an unfinished tween. Slot is now the default: the actual dragged row remains in a candidate slot with all its columns aligned, tweening with its neighbors. Float preserves the comparison where a transform follows the pointer’s original grab offset and the in-flow slot serves as its placeholder. Drop and cancellation settle from the last painted position. Reduced motion skips these tweens.

The Rows tool reserves no side handle or action gutter. Press anywhere on a binding row to select it, then drag to move; double-click a cell to activate text editing or read-only value selection/copying. Pointer pickup waits for movement so the two clicks do not rearrange DOM nodes or compete with cell activation. The active cell allows normal text selection until focus leaves or Escape returns to its row. The derived result row cannot move, but its expression and value follow the same activation rule. Tab into a cell also activates it; Enter/F2 on a row edits its expression. Space on a row begins keyboard movement, arrows preview, Enter commits, and Escape cancels. Normal mode retains single-click editing; insertion immediately activates the new expression.

The shared palette provisionally separates pointer targeting (Edit, Rows, Connect) from structural policy (Refactor, Refine, Free edit). It investigates competing click targets, not a semantic taxonomy: future whitespace/token/delimiter hit testing might combine tools. Buttons can latch otherwise held modifiers. Shared Copy across rows, tokens and forms remains proposed. Local Rows/Connect buttons select the same global tool; local policy menus mirror the shared policy. Option/Alt remains a contextual quasimode. Policy/tool changes cancel active transactions. The two labs are separate documents, not a unified editor: Rows acts in the first, Connect in the second. Shape and Inspect are icon/targeting sketches, not working toolbar tools.

The policy experiment gates **structural commands only**. Typing in the ordinary HTML inputs stays unrestricted. Refactor checks independent arithmetic row movement. Refine includes that and empty-factor filling; Free edit also permits dependency-breaking moves, replacing/moving uses, and populated deletion. Blank draft creation/cleanup and history/reset are administrative exceptions available in all policies. These labels do not establish Hazel semantic guarantees. The design notes relate the proposed operation-set inclusion to Hazelnut Live’s typed, pure hole-filling theorem and its limits.

Backspace from either cell removes a row only when **both** pattern and expression are blank. Cmd/Ctrl+Shift+Backspace requests explicit binding-row deletion; populated rows require Free edit. Plain Cmd/Ctrl+Backspace is not intercepted. The derived result row cannot be removed. Dragging a row outside the **code viewport rectangle**, including its padding but excluding toolbar and status, previews deletion; release commits one undoable removal. Returning inside restores the move preview. Escape, blur and pointer cancellation leave source unchanged.

Reference creation pulls an SVG wire endpoint from a binder to a factor. Word-center anchors and flexible wires are the chosen design; the comparison selectors are gone. Optional hover/focus links use the same thin curve behind text, even outside Connect. Two spring control points provide inertia while endpoints stay exact. Wires use fixed viewport coordinates during dragging/retraction so they can cross the code canvas boundary. On connection, the word opens into the hole, moving following text horizontally. References retain binder IDs.

In Connect, an existing use can be dragged as a word with its wire. The original occurrence stays dimmed until commit; pickup never destroys source. In Free edit, a different factor moves the use (leaving a source hole), and a drop anywhere without a factor target removes it, retracting the endpoint toward its binder with a damped overshoot. An in-canvas miss unplugs just like an outside drop. Returning to the original factor preserves the use; a refused policy, Escape, tool change or lost window cancels. Dragging a new connection from a binder to a non-target cancels with cable retraction, without editing source. Click-to-pick also has click-away cancellation: the next click anywhere without a factor target retracts the cable in every policy. That click is consumed, including on another binder or action button, so it cannot immediately start a new connection. A keyboard-picked existing use also remains intact when canceled by clicking away. Space on a focused use picks it up for keyboard movement; Tab/Enter chooses the destination; Backspace/Delete removes it in Free edit. Undo restores slot identities and cancels a pending retraction. Reduced motion removes spring animation and word opening; stationary wires stop requesting frames. This is a small visual spring model, not a general rope/collision simulation.

The study and native port share the cable renderer and spring constants. Its control points retain position and velocity when switching between viewport dragging/retraction and local landing/hover coordinates. `wire-physics-test.cjs` verifies that this switch (or moving the container) does not introduce a spurious impulse. Attachment keeps the cable visible through the landing phase and resumes hover without a new pointer event.

The inventory schema is `{stages: [...], actions: [...]}`. Change an action's `stage` and its order in `actions` to reprioritize it; retain its stable ID so fragment links and discussion remain meaningful. `study` and `hazel` record coverage independently, with detail text and a `next` task. The builder rejects duplicate IDs, unknown stages and entries in the implemented stage with no working slice. Split partially satisfied actions: Undo recovery is working, persistent stash is not; live furling is working, alternative animation is a proposal. A `story` link opens the corresponding fixed before/after example, never signifies an implemented gesture. Source evidence includes inspected historical/upstream code, which is not proof of live integration.

The two syntax examples and layout studies elsewhere remain their own renderers. This page is an isolated input experiment; implement approved behavior through the live `FurlDocument` source/identity/history model, not by importing this arithmetic parser or scraping the DOM. The [port parity contract](../design/interactions.md#port-parity-contract) records the observable behaviors to preserve and the recommended minimum live slice.
