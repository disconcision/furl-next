Interaction study · 5 September 2026

Writing and reshaping programs.

The old Furl editor makes rows and names tangible. The Big Book extends that idea to scopes, parameters, branches, and helpers. These studies bring those actions together with mouse and keyboard controls.

Proposed interactions, separate from the live Hazel editor. The row lab uses ordinary HTML text inputs and a small JavaScript arithmetic parser, with no Hazel editor or backend. The other examples use fixed programs and preset values. This entire page works offline.

Policy

Tool chooses what a drag grabs; policy chooses which structural changes are allowed. Ordinary typing remains unrestricted in this study. Rows operates study 01; Connect operates study 02. Their local buttons select the same tools. Hold Option / Alt over either study for its tool temporarily.

Tool families and the policy experiment
Edit

Caret, selection, completion, syntax templates and eventually dictation. Ordinary text entry here remains unrestricted; the policy gate covers structural commands only.

Rows

Reorder, insert at gaps, delete; later duplicate or carry dependencies. Copy is an action variant, not another tool.

Connect

Create, move and unplug uses. Later select subexpressions for extraction or inlining. The source and destination choose the operation.

Shape proposed

Comb endpoints and regions: group, resize, abstract parameters, extract helpers and reshape match branches. One tool for lexical extent.

Inspect proposed

Values, calls and branch views. Furling and trace navigation need no source-edit permission; applying a specialization is a separate command.

Refactor → Refine → Free edit is a proposed nesting of allowed actions. Here Refactor checks arithmetic row moves; Refine also permits connecting a binding to an empty hole; Free edit additionally permits breaking dependencies, replacing uses and deleting populated rows or uses. Blank-draft insertion/cleanup, Undo and Reset are available in every policy. These draft operations are editor scaffolding, not a claim of semantic equivalence.

Hazelnut Live proves that well-typed expression-hole filling commutes with reduction in its pure calculus. This supports refinement, but a closure can contain holes and change when they are filled; it is not a guarantee for every displayed value, pattern edit, type edit or effectful program. The small parser here does not implement that theorem. Hazelnut Live §4.

01 Quiet until you reach for structure

Select Rows, or hold Option / Alt while pointing here. Gaps insert; drag anywhere on a binding row to move it. Double-click a cell to edit or interact with its value. There is no separate row handle or action gutter.

Try moving bonus above n. Then try moving twice above n. Refactor blocks the dependency break; Free edit lets you see it.

Editing cells
Drag
Click an expression to edit it. With Rows active, drag a row or double-click a cell.
Underlying source




Mouse · With Rows active, drag anywhere on a row, including over its name, expression, or value. Double-click a cell to edit; double-click a value to select and copy it. The active cell supports ordinary text selection until you leave it or press Escape. Gaps insert; release commits one move. Slot keeps the row in a candidate position with aligned columns; Float lets it follow the pointer. In Free edit, drop outside the editor canvas to delete. The canvas is the code rectangle between the toolbar and status, including its padding; its edge lights up before deletion. Empty draft cleanup works in every policy.
Keyboard · ⌘/Ctrl Enter inserts below the active row; add Shift for above. Tab to a row: Space picks up, ↑ ↓ previews, Enter drops. Escape cancels. When no move is active, Enter or F2 edits the expression; Tab into any cell to activate it. Newly inserted expressions are ready to type into. Backspace removes a row with both cells empty, from either cell. ⌘/Ctrl Shift Backspace requests deletion of the current binding row regardless of contents; populated rows require Free edit. The result row stays.


The refactor gate here is deliberately small: unique names, valid arithmetic, and preserved lexical dependencies. Completely empty draft rows do not block independent moves; their holes remain visible. It is not Hazel’s refactor checker. New rows contain holes and are ordinary source edits, not guaranteed semantic no-ops. Source: old Furl’s row handlers; Big Book 84–88, 94.




02 Carry a reference, leave the binding
Select Connect and pull a connection from a binding to a hole. The endpoint follows you; the name opens in the hole when you connect it. Hover a completed reference to trace it back to its binding.


Inspecting references
Select Connect, then pull width and height into the two holes. Refine permits filling holes; choose Free edit to unplug uses.


Mouse · Pull from width or height to a hole. The flexible wire and word-center anchors are the chosen design. Hover links use that same wire behind the text. Drag an existing use and release anywhere except a factor target to unplug it in Free edit; its wire springs back to the binding. Drop on a factor to reconnect, or press Escape to cancel. Click-to-pick and click-to-place work too: after picking up a cable, click anywhere without a factor target to cancel and retract it. Canceling a connection leaves the program unchanged in every policy.
Keyboard · Tab to a binding; Enter or Space picks it up. Tab to a hole and press Enter. Space on a filled factor picks up that use for moving; Backspace or Delete removes the focused use in Free edit. Escape cancels; ⌘/Ctrl Z undoes. In the live editor, an “Insert reference” chooser at the caret would list in-scope names.
Old Furl implements this for names in later rows. The full editor needs lexical resolution across nested functions, matches, and shadowing. Filling an empty factor is allowed in Refine; replacing, moving or unplugging a use requires Free edit. Pickup leaves the source intact until a permitted drop. A refused or canceled drop restores it; Undo reverses a completed edit.

05 One operation, several ways to reach it
Reuse Hazel’s transformation layer, then project each candidate program into Furl’s layout. A keyboard command, pointer drag, or comb gesture should choose from the same candidates and commit through the same document transaction.
Dragology and gestures can coexist: direction chooses an operation family; candidate states determine the valid destinations. A leftward pull can mean Group while an upward move offers nearby binding slots. We do not need a different editing engine for each gesture.


Source target→Candidate program→Furl preview→One edit + undo


Refactor has to earn its name
Hazel already checks dependencies, capture, and some branch-disjointness conditions. Its registry also includes edits that add holes. We need per-operation guarantees: an unused expression can still fail or diverge, and moving it across a branch can change when it runs.
A preview does not save, evaluate on every pointer move, or fill the undo stack. A source change during a drag cancels the stale preview. A match echo points to the same source occurrence, so it cannot duplicate an edit.
Integrate deliberately, port periodically
Keep furl as the deployment branch. Trial the refactorings snapshot in a separate integration branch: it brings newer Hazel work as well as refactors. The native drag renderer cannot supply Furl’s grid coordinates unchanged.
Keep reusable Hazel fixes in focused commits with native tests. Backport those to the relevant Hazel branch with provenance, and record imported snapshots and returned PRs in a small ledger. This study does not merge branches or create upstream PRs.

06 Voice can fill the text-shaped gap
A small microphone control could dictate into the selected cell, offer a correction, then insert once. Keep the source target and selection while recording; a late transcript must not land in whichever cell happens to be focused later.
Browser speech recognition is the smallest experiment, but support is uneven and audio may be processed by a service. On-device recognition requires capability checks. MDN: SpeechRecognition.
A short recording sent to an authenticated transcription endpoint offers more control. OpenAI, for example, supports transcription context and keyword hints for domain terms; streaming is available if waiting for a completed clip feels slow. The Pages site can host the control, but a service key belongs on a backend. File transcription · Realtime transcription.
No recording or service is enabled here. The practical trial should measure how much correction names, punctuation, and casing need. Provider, retention, latency, and cost remain choices for that trial.
