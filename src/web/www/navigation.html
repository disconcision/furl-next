Same code. Three ways to move between branches.

These sketches keep navigation on the comb and leave the text grid intact. Try them with the nested rails visible. Everything here is self-contained; the examples use preset syntax and values.

01

Click the stem

Click the vertical match stem to advance. Shift-click goes back. With the stem focused, use ← →.

No added marks or packing cost. The gesture is hard to discover, and reaching a distant branch takes repeated clicks. This is the provisional live behavior.

02

Arrows in the stem

Select the vertical stem to reveal a pair of arrows in its own rail. They temporarily cover two short sections of the line. Escape dismisses them.

Direction becomes visible without widening the gutter. The targets remain small, and hiding part of the comb weakens its shape while navigating.

03

A chooser from the fork

Click the horizontal fork to open the branch patterns. Choose one directly, or use ↑ ↓ and Enter. Escape closes the chooser.

Works with many branches and avoids extra gutter width. The temporary menu covers code; using the fork for navigation also displaces its source-reveal action.

The Big Book’s match sequence (slides 37–44) shows parallel branches with a shared scrutinee and repeated result name. Its trace sequence (49–52) adds value columns for repeated calls. I did not find a branch-switching gesture in those sequences; these three gestures are new proposals.

Call inspection in the live editor follows Hazel’s probe idea: select a value, then navigate its recorded calls using the arrows that appear beside it. Branch selection is independent of evaluation: a branch can be displayed even when its values are blank for the current call.
