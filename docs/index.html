An interactive reference · September 2026

Code, with room for its values.

Furl explores a way to work with programs by bringing bindings, expressions, and values into the same view. A sequence of small definitions becomes a common place to read, inspect, and eventually transform code.

A view can be furled into rows or unfurled back into ordinary syntax, one subexpression at a time. These studies explore that movement on a character grid.

The controls work; the values are preset examples. Text editing, evaluation, drag and drop, and animated transformations are still to come.

01 A common shape for bindings

A cell brings a name or pattern beside an expression and its value. A scope collects these cells into a sequence. Furling exposes the smaller definitions inside an expression while keeping their containing scope visible in the comb.

Try unfurling the inner calculation, then the whole program. Toggle bindings, expressions, and values independently; ∫ hides the comb.

02 Leave a place for an argument

03 Let a pattern split the path

A match places alternative patterns beside the same input. Each branch carries its own definitions to a result. Repeated input and result references help the branches read together; the curved comb makes their grouping explicit.

Switch between Some 7 and None, then unfurl the match bridge. Compare a shared and a separate stem under Display options.

04 Compose the same few forms

Let blocks, function literals, and matches share a regular arrangement without losing their distinctions. Here two parameters lead into a definition and then a match. The expression and value columns retain their alignment through the surrounding function and its branches.

Furl the function while leaving its match as code, or reverse the choice. Pattern indentation and the offside comb can be shown independently.

05 One program, several calls

The syntax of a recursive function stays in place as its arguments and intermediate values change. Selecting a call changes which evaluation we inspect. The outer run remains the point of entry; each recursive subtotal leads into another invocation.

Use the call arrows, or click a subtotal value to step into its call. At the empty list, the other branch supplies the result.

06 Turn toward the trace

A program can act as the guide for its own trace. Showing two calls together gives values a home beside the code that produced them. Here the calls take different branches, so each branch also carries the corresponding example’s values.

Hide the expressions to compare values, then restore them to see the computation. On a narrow page, branches stack while their role columns remain aligned.

07 Give a calculation its own name

The let block is a useful intermediate shape for transformations. A sequence of calculations can become a helper; references to the surrounding scope can become its parameters. The familiar rows provide a place to follow what moves and what is left behind.

Toward an editor

Furl will own the surrounding workspace and these views. Hazel will supply the structural editors, language semantics, and value inspection. Small expression and pattern editors should fit into the same quiet grid, with the comb remaining outside the code’s indentation.

This page is the working reference for that interface. New examples and display choices can be tried here as the live implementation develops.
