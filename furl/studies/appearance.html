Names, symbols, and a little character

A place to compare presentation choices without turning every choice into permanent editor chrome.

These are local presentation experiments, not Hazel editors. Generated word names and the optional old-Furl theme are in the live editor; emoji aliases remain deferred; the circle controls below are only a presentation experiment. The simple usage treatment is the live direction.

A name when you need one

New rows draw an unused word from a shared pool, starting with old Furl’s names and continuing with Hazel’s refactoring names. Avoiding both existing definitions and unresolved names prevents accidental capture. You can rename the result normally.

Aliases are allocated once per binding; adding a row does not reshuffle existing aliases.
Candidate symbol whitelist

Start with these visually distinct symbols. On exhaustion, allocate unique pairs in order. This is a binding-to-alias registry, not a hash that can collide. In the editor, copy/paste and an accessible name should retain the source word; a literal Unicode rename would be a separate edit.

This study changes a view alias, not the actual identifier. Switching views should not rewrite the program or consume Undo. The live generator currently makes word names only.

Unused, used once, used more than once

The current unused-name warning carries too much color. The chosen simple scheme follows old Furl: mute unused names, leave single-use names normal, underline names used more than once. Ink, dots and the earlier underline experiment remain for comparison; margin ticks are removed because they compete with indentation. Hover or focus a name to read its exact count.

Counts describe lexical references, not how often evaluation runs. Keep type errors separate from usage styling. Unused-name warning backings are replaced by muted ink; exact counts stay available on demand. Other warnings and type errors remain separate.

The old-Furl family resemblance

The live theme changes the font, palette, shadows and small stable offsets of glyphs. Its measured cells and source identities stay the same. The revised live version uses old Furl’s pink bindings, turquoise values, blue operators/callees, white-shadow unused names, lively hover and fluorescent selection. Holes stay unrotated for caret alignment.

A marker for the entry expression

The current “result” label is derived, so it cannot be renamed. A symbol may make that clearer. My preference is ↳ for the scope’s concluding expression; ◇ suggests a distinguished entry, and ▶ suggests execution but risks looking like a Run button. These are proposals; the live label is unchanged.

One program can still have several editor views. A helper may remain a lexical definition in the same Hazel program while its Furl view is pinned beside the main view. That is different from making it an independent program: parameters, scope and captured variables still matter. Start with one semantic program and allow sibling views of its definitions; choose a separate module/top-level definition model only when visibility and recursion require it. Extracting a helper should decide its lexical destination first, then where its view appears.
